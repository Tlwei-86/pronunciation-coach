## 一、 自动化核验体系概述

本方案用于对 phase3_technical_specification_rfc.md 中规划的所有技术特性进行自动化核对与基线回归。通过单元数学单测、端侧管道注入、ADB 自动化脚本、UI 树 XML 解析及像素级色彩直方图分析，实现全链路无需人工干预的自动化验证。

## 三、 核心需求项专项自动化核验设计

### 3.1 动态唇形追踪与视觉 HUD 渲染核验
* **核验目标**：验证 ML Kit 38 点轮廓提取正常，且屏幕上透明 Canvas 能够根据发音开合动态实时呈现骨骼线与正确的状态光晕。
* **自动化核验流程**：
  1. 向图像分析管道依次灌入标准口型与过度大张口型；
  2. 截取真机唇部 ROI 矩形区域，执行色彩直方图分析；
  3. 标准开度时断言霓虹绿 (#00E676) 像素占比 >= 5%；
  4. 过度张大时断言绯红警告色 (#FF5252) 像素占比 >= 5%，且无绿色；
  5. 读取 SurfaceFlinger 日志，断言渲染刷新率恒定保持 >= 30 FPS。

### 3.2 声学-口型双模态反向推断隐蔽舌位核验
* **核验目标**：验证反演公式对舌位高度与舌位前后的计算解耦无误，且能精准映射到解剖学动作。
* **自动化单测基准矩阵（CI 自动化门禁）**：
  - 标准输入 [F1=600, F2=1200, J=0.24, R=0.42] 断言输出高度 [0.45, 0.58]，前后 [0.42, 0.54]，动作 ACTION_PERFECT；
  - 舌根后缩 [F1=600, F2=950, J=0.24, R=0.42] 断言输出前后 < 0.35，动作 ACTION_TONGUE_RETRACTED；
  - 舌面前拱 [F1=600, F2=1600, J=0.24, R=0.42] 断言输出前后 > 0.65，动作 ACTION_TONGUE_TOO_FRONT；
  - 压舌低张 [F1=800, F2=1100, J=0.48, R=0.35] 断言输出高度 < 0.30，动作 ACTION_JAW_TONGUE_LOW。

### 3.3 流式麦克风录音与自适应 VAD 端点截取核验
* **核验目标**：验证前置 200ms 环形缓冲完整保留爆破音冲直段，且在静音后 400ms 内准确截断发触发信号。
* **自动化测试校验点**：
  - VAD.SpeechStart 在语音开始后 80~120ms 判定触发；
  - 截取的有效 PCM 前置 200ms 爆破音完整保全率 100%；
  - VAD.SpeechEnd 在静音后 350~450ms 内触发截断。

### 3.4 16KB 内存页面对齐与 APK 架构核验
* **核验目标**：彻底消除 Android 15/16 物理页面警告，且仅包含 arm64-v8a 架构。
* **自动化检验脚本**：
  - 校验解包 APK 的 lib/ 目录下无任何 x86、x86_64 或 armeabi-v7a 目录；
  - 校验所有 .so 二进制的 ELF LOAD 段的 Align 属性恒等于 0x4000 (16384)。

## 五、 性能、时延与内存 SLO 自动化判定门禁

每次自动化测试套件执行完毕后，执行硬件指标自动比对：
* **端到端时延**：DualModalOrchestrator: InferenceFinished 时延差值 <= 220ms；
* **物理常驻内存 (RSS)**：dumpsys meminfo 总 PSS <= 210MB；
* **16KB 兼容性**：UI Automator dump 校验零警告对话框。
